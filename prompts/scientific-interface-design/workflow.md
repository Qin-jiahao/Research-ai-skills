# Scientific Interface Design Workflow / 科研软件界面设计工作流

## 中文

### 使用场景

当科研分析工具、数据浏览器、图表生成器或实验记录界面需要需求拆解、状态设计和可用性审查时使用。

### 输入要求

提供用户任务、数据对象、输入输出、错误状态、权限、可访问性要求、目标平台、导出格式和已知约束。

### 输出要求

输出任务流和状态图、页面结构、数据契约、控件与校验、失败和空状态、来源展示、可访问性清单及待测试假设。

### 禁止编造的内容

不得编造用户测试结果、数据质量、运行状态、权限、性能或科学结论。视觉风格不能代替科学证据。

### 信息不足时的处理方式

先列出缺少的用户任务、数据字段、权限和验收标准。只有截图时只能提出原型级问题和条件化建议，不声称界面可用。

### 双语示例

**完整输入：** 提供 RNA-seq 结果浏览器的任务、字段、角色权限、失败状态和导出格式。**预期输出：** 给出状态图、字段映射、错误提示和可访问性检查。

**信息不足：** 只有一张“更好看”的界面截图。**预期处理：** 标记任务、数据、权限、错误状态和验收标准待补充，不判断可用性。

### 来源说明

来源于网络和用户提供的界面设计截图，自行整理汇总；未复制第三方界面或代码。

## English

### Use case

Use this Prompt when a research-analysis tool, data browser, figure generator, or experiment record needs requirements, state design, or usability review.

### Required inputs

Provide user tasks, data objects, inputs and outputs, error states, permissions, accessibility requirements, target platform, export formats, and known constraints.

### Expected output

Return task and state maps, page structure, data contracts, controls and validation, empty and failure states, provenance display, an accessibility checklist, and hypotheses to test.

### Fabrication ban

Do not invent user-test results, data quality, execution status, permissions, performance, or scientific conclusions. Visual style is not scientific evidence.

### Missing information

List missing user tasks, data fields, permissions, and acceptance criteria first. With only a screenshot, return prototype-level questions and conditional suggestions and do not claim usability.

### Bilingual example

**Complete input:** Supply tasks for an RNA-seq results browser, fields, role permissions, failure states, and export formats. **Expected output:** Return a state map, field mapping, error messages, and accessibility checks.

**Incomplete input:** Only a screenshot described as “make it look better” is supplied. **Expected handling:** Mark tasks, data, permissions, failure states, and acceptance criteria as missing and do not assess usability.
